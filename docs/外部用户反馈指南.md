# 外部用户反馈指南（脱敏）

**状态**：现行（O4）  
**更新日期**：2026-07-28  
**适用**：安装问题、真实项目任务结果、Provider 兼容问题、普通缺陷  

本指南帮助你在**不泄露密钥与项目机密**的前提下反馈 MAO。收集目标是 v0.2.0 进入条件中的外部安装与真实任务证据，不是上传你的代码或账单。

## 1. 绝对不要粘贴

| 类别 | 示例 |
|---|---|
| 密钥 | `sk-...`、`ark-...`、`Bearer ...`、`.env` 全文 |
| 会话与运行态 | `sessions/**`、`memory/**`、完整 RunJournal JSON |
| 项目机密 | 客户名、内网 URL、未开源业务源码、数据库连接串 |
| 可识别路径 | `C:\Users\真实姓名\...` 中的姓名段（可改成 `C:\Users\<user>\project`） |

若密钥已误贴到公开 Issue：立刻在 Provider 控制台**轮换**，并编辑/删除该评论。

## 2. 推荐提交渠道

在仓库 **New Issue** 选择模板：

| 模板 | 何时用 |
|---|---|
| **安装 / 首次配置反馈** | pipx 失败、无命令、Web 起不来、配不上 Provider |
| **真实项目任务反馈** | 在真实仓库上完成或失败了一次任务（O4 核心） |
| **Bug report** | 可复现的产品缺陷 |
| **Provider compatibility** | 某模型/流式/工具协议不兼容 |
| **Security advisory** | 安全漏洞 → 走私密通道，不要开公开 Issue |

也可先把文字交给本机脱敏：

```bash
# 源码树内
python scripts/sanitize_feedback_text.py path\to\log.txt

# 或管道
type log.txt | python scripts/sanitize_feedback_text.py
```

## 3. 最小可诊断信息（默认字段）

几乎所有反馈都应包含：

1. **MAO 版本**：`mao --version`  
2. **OS**：Windows / Ubuntu / macOS  
3. **Python**：`python --version`  
4. **安装方式**：pipx / 源码 editable  
5. **权限模式**：`approve` / `readonly` / `auto`  
6. **稳定错误码**（如有）：`authentication_error`、`connection_error`、`invalid_request_error`、`quota_exceeded` 等  
7. **脱敏后的复现命令**（无 Key）  

可选：

- Provider **族**（「火山 Coding Plan」「OpenAI 兼容」），不要写账号 ID  
- 主模型**别名**（配置里的名字）  
- 是否误改了项目文件（是/否）  
- 是否愿意再次使用（会/不确定/不会）  

## 4. 真实任务反馈怎么写才有用

好的示例（脱敏）：

```text
版本：MAO 0.1.0b7 / Windows / Python 3.11
入口：mao 对话，权限 approve
任务：只读梳理前端 src/routes 结构（不开业务名）
Provider 族：OpenAI 兼容；模型别名：my-main
结果：完成；约 6 次 read_file，无写入
摩擦：首次配置 Base URL 时漏了 /v1
会否再用：会
```

差的示例：

```text
Key 是 sk-xxxxx，项目在 D:\客户甲\保密系统，日志见附件 session.yaml
```

## 5. 安装失败时优先自检

```bash
mao --version
mao web --help
# 源码开发者：
python scripts/first_run_acceptance.py
python scripts/verify_distribution.py
```

完整空目录路径见 [`acceptance/首次安装验收清单.md`](acceptance/首次安装验收清单.md)。

## 6. 维护者如何使用反馈

- 安装类 Issue → 计入「成功安装」统计（条件 #1）时，需能判断**是否装上并跑到配置页**。  
- 真实任务类 Issue → 计入「真实项目任务」时，需有任务类型 + 结果 + 权限模式，且无密钥。  
- 不得把单次成功或未授权付费 smoke 写成产品完成率结论。  
- 需要复现时，优先要错误码与最小命令，而不是用户项目副本。
