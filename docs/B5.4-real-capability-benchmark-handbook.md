# B5.4 Real Capability Benchmark Handbook

**Status**: Offline framework and Harbor adapter complete; private small samples have been run; multi-model real acceptance is paused

**Goal**: Under the same tasks, workspaces, execution depths, and verifiers, separately measure fixed single-model, auto-route single Agent, and multi-model collaboration.

## 1. Contracts Completed So Far

- `fixed-single`: fixed primary model, Workers disabled; single-model baseline.
- `auto-route`: explainable routing allowed, Workers disabled; measures routing value only.
- `multi-model`: explainable routing allowed and forces qualified engineering tasks into Orchestrator/Worker/Reviewer; only `standard/deep`.
- `mao benchmark-agent`: non-interactive production Agent flow; JSON output includes routing, collaboration, trajectory, tokens, cost, files, and engineering audit facts.
- `MaoHarborAgent`: matches Harbor's current `BaseInstalledAgent` interface; pins wheel or Git commit via `MAO_INSTALL_SPEC`; runs MAO in-container with a redacted Provider template.
- All strategies have `allowed_models`; fixed strategy automatically allows only the primary model; auto-route/multi-model strategies must declare at least two candidates. Unauthorized models are excluded from Gateway candidates and the failover chain before call.

Offline acceptance commands:

```bash
python -m pytest -q tests/test_benchmark_agent.py tests/test_engineering_benchmark.py
python scripts/benchmark_engineering.py
```

The second command runs 3 strategies × 3 repeats on 6 classes of programmatic tasks, totaling 54 synthetic results. It only validates control variables, isolation, reporting, and stability (`provider_calls=0`) and must not be used as a real-model performance conclusion.

## 2. Required Authorization Form Before Real Calls

Project owner must confirm once:

1. Model alias for `fixed-single`.
2. Allowed model alias list for `auto-route`.
3. Allowed model list for `multi-model`, and which model each role uses in the workers config.
4. Repeat count per task/strategy, and Provider attempt stop threshold. Attempts are reserved before each real network request; requests after the threshold must not be sent.
5. Local cost stop threshold and Provider account-side hard quota. Local billing can only happen after usage is returned; a single request may cross the threshold, so the true hard cap must be set on the Provider side.
6. Result visibility: `private`, `aggregate`, or `full`.

Code layer uses `LiveBenchmarkAuthorization` and a shared `LiveBenchmarkSpendGuard` across all strategies. Without an authorization object, the real runner should not be created. Cost remains a post-paid metric confirmed only after Provider usage returns; attempt count is a local hard cap; true hard cost cap still requires Provider account configuration.

## 3. Harbor / Terminal-Bench Prep

Current adapter target is [Harbor](https://harborframework.com/docs/agents) `0.20.x` and [Terminal-Bench 2.0](https://www.tbench.ai/). Harbor `0.20.x` requires Python 3.12; MAO default install still supports Python 3.11/3.12; only the `[benchmark]` environment must use 3.12. Harbor is not a default MAO dependency:

```bash
python -m pip install -e ".[test,benchmark]"
harbor run --help
```

`MAO_INSTALL_SPEC` must pin a reproducible version; formal data must not use floating `main`/`latest`:

```text
git+https://github.com/Wanbinyu/multi-agent-orchestrator.git@<full-commit-sha>
```

Provider template `api_keys` must only use environment variable references, e.g. `${ARK_API_KEY}`. Do not write real keys into YAML and Base64 them; Base64 is not encryption. Real keys are injected via Harbor `--ae`; templates via `MAO_PROVIDERS_CONFIG_B64`.

Example strategy args:

```bash
--agent src.integrations.harbor_agent:MaoHarborAgent
--ak strategy=fixed-single --ak main_model=glm-ark --ak allowed_models=glm-ark
--ak execution_depth=standard --n-concurrent 1
```

For auto-route use `strategy=auto-route`; for multi-model use `strategy=multi-model`; the latter two require comma-separated `allowed_models` with at least two aliases. Reports save `actual_models` separately; strategy labels must not replace actual call facts. First round: one public task, serial, one repeat; check container writes, verifier, `mao-result.json`, trajectory, and cost before expanding.

## 4. Result Interpretation Constraints

- Completion rate is judged by the same deterministic verifier, not by the model claiming "done".
- Token/cost conclusions must state whether the Provider returned real usage; unknown pricing must not generate savings claims.
- Model, execution depth, routing, and collaboration are four independent variables; reports must not merge them into one "MAO is stronger" conclusion.
- Failed results must be retained. If multi-model does not improve a task class, record it as a routing boundary; do not delete data.
- Terminal-Bench task text, private projects, keys, and non-redistributable artifacts do not enter public reports.
