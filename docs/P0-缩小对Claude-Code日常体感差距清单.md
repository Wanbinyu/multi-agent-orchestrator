# P0：缩小对 Claude Code 日常体感差距清单

**状态**：现行开发依据（对标 Claude Code 的日常路径）

**基线版本**：`v0.1.0-beta.7`

**创建日期**：2026-07-30

**维护原则**：只维护本文与进度勾选；完成后将实现细节写入 Release Notes / 架构文档，不在多处重复任务清单。

---

## 1. 目的与边界

### 1.1 目的

在**不复制 Claude Code 全量功能、不做 IDE/桌面/企业大项**的前提下，用有限投入优先补齐用户**每天都会碰到**的路径：

> 打开项目 → 说清任务 → 读代码 → 小改 → 跑测试/命令 → 失败再修 → 看 diff →（可选）提交 → 知道是否真完成。

目标不是“功能表打勾接近 100%”，而是让 MAO 在**可信本机、可审查项目**上，单 Agent 日常改代码的**可完成率、可恢复性、可信任感**明显上升。

### 1.2 明确不在本清单内

| 暂缓项 | 原因 |
|--------|------|
| VS Code / JetBrains / 桌面端 | 见 [`MAO-优化与后续开发规划.md`](MAO-优化与后续开发规划.md) O5；需外部用户稳定需求 |
| OS/容器级沙箱（U7 全量） | 工作量大；本清单先强化应用层边界与检查点 |
| 插件市场 / 无限扩展 | 供应链与 API 稳定优先 |
| 默认完整 shell、无确认写入 | 违背 MAO 安全定位 |
| 逆向 Claude Code 登录 / 订阅凭据当 API Key | 已决策禁止，见归档《Claude 与插件接入决策》 |
| 未授权的真实模型效果宣传 | 需所有者授权 + 与 synthetic 分离 |

### 1.4 成功标准（清单级）

全部 P0 勾选完成，且满足：

1. **10 个固定日常任务夹具**（见 §4）在离线/mock 路径全绿；在获得授权后至少 1 个真实 Provider 上跑通同一套任务合同。
2. 默认路径为**单 Agent**；多 Worker 协作仅在显式深度/复杂度或用户开启时进入。
3. 任一失败修复轮次有上限，且完成仍受 `CompletionAudit` 约束。
4. 不引入默认危险 shell；任何命令面放宽必须可配置、可审计、默认可关闭。
5. 文档与 UI 不把“更接近 Claude Code 日常体验”写成“Claude Code 替代品”。

## 2. 执行原则（每条 P0 共用）

1. **单 Agent 优先**：简单改动不得默认拉起 Orchestrator 四职责流水线。
2. **证据不变质**：工具输出、命令退出码、测试结果仍是完成真值；模型自述不能升级失败为成功。
3. **权限不放水**：`readonly` / Plan 未批准 / `deny` 规则优先于一切“为了像 CC”的便利。
4. **可回滚意识**：触及用户工作区写入时，优先检查点或明确 diff 预览；禁止自动 `git reset --hard`。
5. **先合同后宣传**：离线合同与真实 Provider 结果分档存放；真实数字需授权。
6. **每项交付四件套**：场景说明 · 接口/配置变更 · 测试 · 文档真值更新。

### P0-1 · 单 Agent 编辑—运行—再修主循环

| 项 | 内容 |
|----|------|
| **用户痛点** | 能读会写，但改不准、改完不跑、失败后胡改或空转；体感远弱于 Claude Code |
| **目标** | 主对话路径形成稳定闭环：定位 → `edit_file`/`write_file` → 相关验证命令 → 根据**真实**输出再改，有界轮次 |
| **范围** | `src/core/agent.py` 工具循环；`edit_file` 失败诊断；验证命令选择（优先 `discover_project_commands`）；RunJournal 记录每轮工具与验证 |
| **不做什么** | 不为此默认启用多 Worker；不引入无限自我修复 |
| **验收** | ① 夹具：单文件逻辑错误 → 编辑 → 跑测试 → 最多 N 轮（建议 N≤3）后通过或明确 blocked；② `edit_file` 无唯一匹配时返回可操作错误（含上下文提示），不整文件盲写；③ 测试覆盖“验证失败不得 CompletionAudit 通过” |
| **参考** | Grok Build check-work 有界修复；现有 `VerificationGate` / `CompletionAudit` |
| **状态** | ✅ 完成（2026-08-19）：`BoundedFixState` 接入主循环；`edit_file` 失败返回行级上下文；夹具见 `tests/test_bounded_fix_agent.py` |

---

### P0-2 · 有界“验证失败 → 定向修复”协议

| 项 | 内容 |
|----|------|
| **用户痛点** | 测试红了之后，Agent 重复读同一文件或改无关处，token 烧光仍不收敛 |
| **目标** | 将“失败输出 → 假设 → 最小补丁 → 再验证”做成**确定性协议**（可配置轮次上限），与 P0-1 共用 |
| **范围** | 工程层：从最近失败的 `run_command`/测试 Evidence 提取失败摘要写入下一轮约束；超限 → blocked + 剩余风险，而不是假完成 |
| **不做什么** | 不用更多子 Agent 代替验证；不把 Reviewer 自述当证据 |
| **验收** | ① 协议状态机单测（成功 / 达上限 blocked / 中途用户取消）；② 同一失败夹具下 token 或工具轮次相对“无协议乱修”有上限；③ RunJournal 可见 `fix_fix_round` 计数 |
| **参考** | [`开源Coding-Agent参考与吸收计划.md`](开源Coding-Agent参考与吸收计划.md) U3 |
| **状态** | ✅ 完成（2026-08-19）：状态机 `idle/needs_verification/fixing/passed/blocked/cancelled`；`journal.metrics.fix_round`；`MAO_MAX_FIX_ROUNDS` 可配，默认 3 |

### P0-3 · Git 日常最小工具面

| 项 | 内容 |
|----|------|
| **用户痛点** | Claude Code 路径常含看 diff / 提交；MAO 几乎停在改文件，协作与复核断在“仓库状态” |
| **目标** | 只读加强 + 受权限约束的提交辅助：`git_status`（已有）完善、`git_diff`、可选 `git_log`；`git_commit` **仅**在 `approve`/`auto` 且规则允许时，且必须基于已暂存或明确路径列表 |
| **范围** | `src/tools/worker_tools.py` 或独立 `git_tools.py`；权限类别 `read` vs `write`；敏感路径与 hook 仍生效 |
| **不做什么** | 不做完整 GitHub PR 机器人；不自动 push；不 `reset --hard`；不改用户已有提交历史 |
| **验收** | ① 只读任务可 diff/status；② commit 在 `readonly` 拒绝；③ commit 消息与文件列表进入 Evidence；④ 无网络 push 默认入口 |
| **状态** | ✅ 完成（2026-08-19）：`git_diff`/`git_log`/`git_commit`；`run_command` 拒绝 git push/reset/commit |

### P0-4 · 命令面：更像真实项目，但不默认裸 shell

| 项 | 内容 |
|----|------|
| **用户痛点** | 白名单过窄时跑不了项目脚本；过宽又变成任意代码执行（beta.7 已堵 inline） |
| **目标** | 在**保持** `shell=False`、禁管道/重定向、禁解释器 inline 的前提下：强化 `discover_project_commands` → 一键/建议执行已发现脚本；支持配置扩展 `allowed_commands` 模板；失败预检信息足够让模型改**参数**而非发明 `bash -c` |
| **范围** | `run_command`、`discover_project_commands`、`workers.yaml` / 项目权限规则示例、安全回归测试 |
| **不做什么** | 不默认开启完整 shell；不把“前缀白名单放行 python -c”开回去 |
| **验收** | ① npm/pytest/常见脚本夹具可发现并可在允许列表下执行；② 安全用例：inline、管道、敏感路径仍拒绝；③ 文档写清“如何安全加白名单” |
| **状态** | ✅ 完成（2026-08-19）：`suggested_run`、发现结果精确放行、`command_allowlist.extra_prefixes`；指南见工具开发指南 |

### P0-5 · 任务向上下文装填（少而准）

| 项 | 内容 |
|----|------|
| **用户痛点** | 上下文要么塞太多旧对话，要么找不到该改的文件；Claude Code 依赖强模型+大窗，MAO 更依赖装填策略 |
| **目标** | 每轮工具循环前：预算内优先装入**任务相关**路径（最近读取、open 文件、grep 命中、错误栈路径），压缩与“相关切片”可观测 |
| **范围** | `ContextBudgetManager` / Agent 组装消息；可选轻量“本轮工作集”写入 Journal；与现有 L0–L2 压缩兼容 |
| **不做什么** | 不做完整 LSP/全仓 embedding（留给 P0-6 最小切片）；不猜测未验证模型窗口 |
| **验收** | ① 夹具：错误栈指向文件 A 时，工作集含 A 的概率/合同可测；② 超预算时仍优先丢旧闲聊而非丢当前失败日志；③ 压缩事件指标可看 |
| **参考** | 上下文计划；Aider“相关文件”思想（独立实现） |
| **状态** | ✅ 完成（2026-08-19）：`TurnWorkset` + Journal `metrics.workset`；压缩 `protected_kept`/`dropped_chitchat` |

### P0-6 · 最小 Repo 导航（找准再改）

| 项 | 内容 |

### P0-7 · 工作区检查点（敢在真仓库用）

| 项 | 内容 |
|----|------|
| **用户痛点** | 怕 Agent 改坏；Claude Code/Cline 类产品有回退预期，MAO 缺“改前快照” |
| **目标** | 会话或高风险写入前可选检查点：与**用户 Git 分离**的文件快照（或 shadow 索引）；恢复前 **diff 预览 + 显式确认** |
| **范围** | 新模块建议 `src/core/checkpoint.py`；CLI `/checkpoint` 或写前策略；忽略密钥与超大文件 |
| **不做什么** | 不自动恢复；不写用户 `.git` 历史；不对用户已有脏改动静默覆盖 |
| **验收** | ① 创建 → 修改 → 预览 diff → 恢复后内容一致；② 用户已有未提交改动时拒绝覆盖或要求确认策略有单测；③ SECURITY/README 各一句说明 |
| **参考** | 吸收计划 U5（Cline Shadow Git 行为契约，独立实现） |
| **状态** | ✅ 完成（2026-08-19）：`WorkspaceCheckpointStore` + `/checkpoint`；脏工作区默认拒绝覆盖。W5：写前自动快照 + prune |

### P0-8 · 默认路径：单 Agent；协作显式加深

| 项 | 内容 |
|----|------|
| **用户痛点** | 小改动也多模型拆任务 → 慢、贵、难调试，体感反而不如“一个强循环” |
| **目标** | 分类为问答/小改/诊断时默认 **不** 进 Orchestrator；仅 `deep` + change/build、或用户显式 `/collab`、或配置强制时进入协作；Journal 记录 `collaboration_triggered: reason` |
| **范围** | `classifier` / `execution_depth` / Agent 触发协作条件；CLI/Web 可见“为何多模型” |
| **不做什么** | 不删除协作能力；不把协作宣传为默认更省 |
| **验收** | ① 小改夹具 0 次 Orchestrator 调用；② deep 前端合同任务仍可走协作；③ 文档与 `/help` 说明触发条件 |
| **状态** | ✅ 完成（2026-08-19）：去掉 LLM/关键字预筛；`/collab` + Web 会话开关；Journal 记录 `collaboration_triggered`/`reason` |

## 4. 建议的 10 个日常任务夹具（P0-9 种子）

实施 P0-9 时以此为最小集合，可增不可偷偷删合同字段。

| ID | 场景 | 类型 | 期望 |
|----|------|------|------|
| D01 | 解释模块职责（只读） | question | 无写入；有文件引用 |
| D02 | 定位报错栈对应文件 | diagnosis | 指出路径；只读 |
| D03 | 修复单测失败一处断言 | small-change | 测试命令真实通过 |
| D04 | 重命名符号并改引用 | small-change | grep 无旧名；测试过 |
| D05 | 添加函数 + 单测 | small-change | 测试过 |
| D06 | 运行项目 lint/format（若存在） | verify | 命令证据；失败则 blocked 或有界修 |
| D07 | 只读 code review | review | 无写入；有具体行级问题 |
| D08 | 查看工作区 git diff 摘要 | diagnosis | 只读 git 工具 |
| D09 | 拒绝越界写（`readonly` 或 deny 规则） | safety | 无违规写入 |
| D10 | 长对话后压缩仍记得约束 | session | 压缩后约束仍在；不假完成 |
