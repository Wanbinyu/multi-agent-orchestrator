# 首次安装验收清单（空目录 / 新项目）

**状态**：现行  
**更新日期**：2026-07-28  
**基线**：`v0.1.0b7` / `main`  
**目标**：任何人 clone 或 pipx 安装后，在**自己的空项目目录**里 10 分钟内完成：安装确认 → 打开配置界面 →（可选）填自己的 Key → 只读任务。

> 原则：GitHub 上不带真实 API Key；Key 只出现在本机 `.env` / 本机 `config/providers.yaml`（均被 gitignore）。

## 1. 自动化命令

```bash
# 发行包：干净 venv + 空目录 CLI/Web（零 Provider）
python scripts/verify_distribution.py

# 空目录首次路径（零 Provider，推荐每次改入口后跑）
python scripts/first_run_acceptance.py

# 额外：本机 Key 的只读 Agent 一轮（不打印密钥；失败默认不阻断离线门）
python scripts/first_run_acceptance.py --with-live

# 若要求 live 也必须成功：
python scripts/first_run_acceptance.py --with-live --require-live
```

## 2. 人工 10 分钟路径

在**任意空项目目录**（不要在安装目录里堆业务代码）：

| 步 | 操作 | 期望 |
|---|---|---|
| 1 | `pipx install git+https://github.com/Wanbinyu/multi-agent-orchestrator.git` 或源码 `pip install -e .` | 安装成功 |
| 2 | `mao --version` | 打印 `MAO 0.1.0b7`（或当前版本） |
| 3 | 空目录非交互 `mao`（无 TTY） | 退出码 **2**，提示用 `mao web` 或交互终端；**不写文件** |
| 4 | `mao web --no-open` | `GET /health` → `{"status":"ok"}`；首页可配置 Provider |
| 5 | 在 Web/向导中填入**自己的** Key，保存 | 只生成项目内 `.env` + `config/providers.yaml`（勿提交） |
| 6 | 权限建议 `readonly` 或 `approve` | 首次任务不要用 `auto` |
| 7 | 提问：「只读检查当前目录文件列表，不要修改」 | 有结构化/可读回复；目标项目无写入 |

### 本机 Provider 现状（不公开密钥）

探测时（脱敏）：

- **火山 Coding Plan（ark / volcengineark）**：`InvalidSubscription` — 账号 CodingPlan 未订阅或已过期，需在火山控制台续费/开通。
- **kimi（anthropic 协议）**：`INVALID_API_KEY`。
- **kimi1（openai 兼容代理）**：极简 `chat.completions` 可通；完整 Agent 回合可能因 `base_url` 缺 `/v1` 或端点返回 HTML 而失败。产品已对「HTML 非 JSON」给出明确错误提示。

**结论**：

1. **产品空目录安装路径可用**（不依赖任何付费 Key）。  
2. **「配 Key → 只读成功」依赖使用者有效的 Provider**；当前开发机上主用 Coding Plan 已过期，需所有者修复订阅或改用可用模型后再做 live 绿通。  
3. 这不阻断「陌生人安装 + 用自己的 Key」叙事；O4 仍应邀请外部用户用**他们自己的**套餐验收。

## 4. 验收通过标准

| 门 | 必须 |
|---|---|
| 离线 / 分发 | `verify_distribution.py` 与 `first_run_acceptance.py` 退出 0 |
| 人工 | 空目录可打开 Web 配置页；未配置时 CLI 行为符合表 |
| Live（可选） | 至少一个 Provider 连接成功 + readonly Agent 一轮有正文；密钥不出现在日志 |

## 5. 发现即修的优先级

1. 首启文案/退出码回归（已由脚本锁住）  
2. OpenAI 兼容 `base_url` 缺 `/v1` 时的提示（已有错误文案；可在配置 UI 预填提示）  
3. 本机 Key/订阅问题 → **用户侧**，不写进仓库  
4. 不把 `work/`、`.env`、真实 `providers.yaml` 推上 GitHub
